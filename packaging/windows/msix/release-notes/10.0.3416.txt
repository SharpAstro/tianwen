FIRST, AUDIT WHAT THE LISTING ALREADY CLAIMS
================================================================================
A standing step, not a formality, and the one most easily skipped because it is
about the LAST release rather than this one. Open the previous record's What's New
block and ask of every sentence whether it is still true. Three ways it goes wrong,
all of which have happened:

  - A claim goes STALE. 7.1.1627 told users to press O for the sky map; the sky
    then moved to its own key, so anyone following the live listing pressed O
    three times and never reached it.

  - A claim was WRONG WHEN WRITTEN. 7.1.1627 promised that a tilted galaxy rings
    as the disc it is. The overlay ellipse carried two independent reflections and
    was plausible at some angles and correct at none, which is how it passed
    review; it took an independent check (the direction to NGC 206, a star cloud
    lying ON M31's major axis) to see it.

  - A NUMBER was measured on the wrong artifact. 9.0.1940's draft claimed the
    download was "around 8 MB smaller" because four driver files removed from the
    install weigh 8.2 MB on disk. An msixbundle is compressed, so the figure
    crossed a compression boundary untested; measured on the bundle a user
    actually receives it was 150,270,411 bytes against 152,858,681, about 2.5 MB,
    and not even that was attributable to the drivers, since 376 commits sat in
    the same span. Caught before submission and the figure was dropped entirely.
    THE RULE: a number in the block is measured on the artifact the user receives,
    never on the inputs that built it. Prefer no figure to a qualified one.

Anything that fails the audit belongs in the block below as a CORRECTION, and it
outranks a new feature for the space: a user acting on a wrong instruction is worse
off than one who has not heard about a new button. Record the finding here too, so
the next release knows what was corrected and why.

----- BEGIN WHAT'S NEW -----
A correction: the soft clip has moved
Our last notes said B and H step Boost and the soft clip. B still steps Boost, but H now shows the histogram (Shift+H for a log scale), and the soft clip is set from the Tone button.

Planetary videos stack themselves
Open a SER capture and press Shift+K: the viewer works out which planet it is and how the capture was taken, stacks the best frames, sharpens the result and saves the master beside the video. K switches between the raw frames and the stack.

One Enhance button
The sparkles button opens one Enhance panel: deep-sky processing for a nebula or galaxy, planetary sharpening for a planet. A new Background panel neutralises the sky's colour and darkens it to an even level, on by default, and enhanced stars keep their colour.

Also in this release
- Each file remembers how you last displayed it. Ctrl+Shift+R resets it.
- Show stars with S, then click one to see its measurements.
- Large stacked masters (FITS, compressed FITS and TIFF) free their memory after opening and read it back from the file when needed.
- Right-click a file in the list to copy its full path or open its folder.
- Save starts in the opened file's folder, and a saved PNG or JPEG records how it was rendered.
- The pixel readout shows the file's own values.
----- END WHAT'S NEW -----

Which way to cut if it goes over: the headed sections are the release and the
bullets are the tail, except that a bullet CORRECTING a live claim is cut last of
all. Record here what was left out, so the next writer knows what is owed rather

Correction (soft clip). "feat(viewer): H is the histogram, and the soft clip gives
up its key" (2026-09-24). ViewerShortcuts now declares "H / Shift+H" as histogram /
log scale and "B / Shift+B" as curves boost / curve mode, with the soft clip on the
Tone panel. Goes first because a user following the live listing presses H and gets
a histogram.

Planetary Auto view. "feat(viewer): Best stack of a recorded capture in tianwen-fits,
the routine planetary-stack runs, its telescope remembered" (#1159), "feat(viewer):
the Best view folds into Auto, the panel's choices given to it" (#817), "feat
(planetary): AUTO reads what a capture is and stacks it at the defaults, in the CLI
and the viewer" (A4, #1391). Shift+K is now "Full stack: the whole capture identified and
stacked once, written beside it (SER)"; K is "Raw / Stack: Live". The frames tell Jupiter
from Saturn only, so a capture of another planet relies on its path or header to be
named; the copy says "works out which planet" and is true where it can.

Enhance and Background. "feat(viewer): the sparkles button opens one Enhance
popover, deep-sky half first" and "...the planetary sharpening moves from the info
strip into the Enhance popover" (#1345); "feat(viewer): a Background popover, the
sky's neutralisation and a background reduce on by default"
(ViewerState.BackgroundReduceEnabled = true, standing down in the planetary
stretch); "feat(viewer): the stars keep their colour, a Star colour dial and the
magenta taken out", and the star split ("an enhanced frame keeps its star split").
The background reduce changes how an untouched master LOOKS on first open, which is
why the copy says it is on by default.

  - File list menu: "feat(viewer): right-click a file-list row to copy its full path

  - Save: "fix(viewer): Save starts in the opened file's folder" (P35); "feat

  - Readout: "fix(viewer): the pixel readout quotes the source's own counts, not

KNOWN ISSUES IN THIS BUILD
================================================================================
Carry the previous record's list forward item by item and mark each one Unchanged,
closed, or changed. A known issue that quietly vanishes between records is one
nobody decided about.

Carried forward from 9.0.1940 (2026-09-21). Reviewed 2026-10-28 only where marked;
re-check the rest at dispatch.

  NEW    TIFF masters TianWen wrote BEFORE this release keep their float planes
         in memory: the readout declines a segment over 4 MB, and the old writers
         put a whole page in one strip ("fix(viewer): TianWen's float TIFF
         writers bound their strips...", #1853). New exports use strips of about
         1 MB and are served. Third-party TIFFs with huge strips, gzip FITS and
         CR2 likewise stay in memory, by decision.

  P21    Single-channel views of a mosaic show the raw mosaic, not the separated
         colour planes (a shader change).

  P11.2  The ? panel names missing SAS AI weights but cannot fetch them from a
         Store install.
         CLOSED (reviewed 2026-10-28): the SETI Astro tier was removed on
         2026-09-26 (its licence allows use only within SASpro), so nothing
         loads or names its weights any more.

  P9/P10 Unconfirmed, neither reproduced since first report.

  SPCC   Broadband only; narrowband blocked on data (per-star Gaia DR3 xp_sampled
         spectra), not on maths.

  Layout Below about 730 px of window width the image pane reaches zero width and
         the histogram overlay lands on the file list.

  About  The About banner concatenates run attempt onto the version (9.0.NNNN1 for
         attempt 1); FileVersion is correct.

  CFA    The SER frame-by-frame histogram sits a mosaic out.

  HDR    A KNOWN GAP rather than a bug: the Tone panel names display HDR and cannot
         offer it, and the reason it gives is about the viewer rather than the
         user's GPU, because nothing in the build asks the GPU what its surface
         offers. Closed by P2 of docs/plans/hdr-display.md.

  Holes  The number of interior holes filled at load is on the document
         (AstroImageDocument.InteriorHolesFilled) but is not shown in the info
         strip or the status bar, so a user cannot see that pixels were
         interpolated.

  Crop   A deliberate refusal rather than a defect: an edge whose profile never
         settles, or settles only within one window and not a wider one, is
         DECLINED and left uncropped. Correct, but it looks like auto crop doing
         nothing on a frame that visibly has a ramp, and nothing says which edges
         were declined or why.
