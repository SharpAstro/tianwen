Click a star or galaxy to see what it is
Left-click any catalogued object on the image for a panel with its name, type, magnitude, and altitude and rise/transit/set at the moment the picture was taken. The ring now traces the object's own shape, true axis ratio and position angle, so an inclined galaxy like M31 rings as the tilted disc it is. Right-click opens it in the web sky atlas.

The night sky behind your photograph
Press O for a sky map drawn behind the image and aligned to its plate solve: the same stars, constellation lines and deep-sky catalogue as the sky atlas, exactly where your picture sits on the sky. A floating panel toggles any of ten layers.

Crop a stacked master to the area every frame covered
The new Crop button trims the ragged, under-exposed border a stack leaves behind. The crop carries through to the plate solution, saved files, the A/B comparison and the AI enhance.

Also in this release
- Save the annotated view (grid, markers, labels); every save honours the crop.
- A/B accounts for a crop instead of warping the "before" half.
- Statistics collapse into a table; white balance moves to a toolbar popover.
- The "?" panel can report a problem with your version and logs attached.
- Touchscreen pinch-to-zoom works again.
- Hold Space to pause a blink, release to resume.
- The auto stretch stops claiming a colour calibration it never measured.

Viewer - object selection and the sky backdrop (P28, P34, and the atlas plan)
  b6852312  A left click SELECTS the catalogued object under it. The resolver
            applies the OVERLAY's type gate - without it a click on M42's core
            answered "HH 1146" - and ignores extent, so at a nebula's centre
            "nearest" can still answer an embedded star.
  48e62beb  The selection gets its own floating panel, with Alt/Az and
            rise/transit/set baked at the CAPTURE instant, never a live clock.
  4162d98a  ObjectInfoPanel becomes shared between the viewer and the atlas, so
            the box comes from the panel rather than literals beside it
            (aae5169e).
  8d8b1125  The ring traces an extended object's own ellipse.
  fe875c76  ...and the ring's ANGLE only ever sized a bounding box, so it never
            actually rotated. Found on M31: PA 35 degrees drew as an upright,
            barely-elongated blob instead of its true 2.5:1 tilt. The rotated
            polyline walk now lives once, in OverlayEngine, shared by the live
            GPU overlay and the CPU annotated-save export, which had drifted
            into a second (correct) copy. Pinned by a GPU/CPU parity test.
  3ac9da5a  P34. A tap resolves against what is DRAWN before it asks the
            catalogue, and the ring's name is the selected object's only label.
  afa097d6  The sky the photograph came from, drawn behind it; 03108047 makes
            grid and objects one button walking a context ladder on O.
  2447e721  The sky's LINES cross the photograph while its IMAGERY stays behind
            it; 8957181a gives the grid one switch with two faces.
  2dc26b09  The grid hands over by DISTANCE from the tangent point, not by field
            of view - a nominal FOV says nothing about how far the deprojection
            has been extrapolated.
  d476162b  The sky map's ten layers get a panel instead of ten letters nobody
            can see; e183a2a5 / a61a00ae / 0aea6710 / 35d4099f make it movable,
            rollable and recessive, over DIR.Lib 8.16's FloatingPalette
            (a2f72e5c).
  b7b5b877  The pan lets go of the frame while the sky is behind it.

Viewer - auto-crop (P25) and the crop's lifetime
  cf42304e  P25. Crop to the area every sub covered. Two tiers: the master's own
            coverage plane from a MAPKIND=COVERAGE sidecar, else a noise walk
            whose reference is the edge's OWN level just inside, since a drizzle
            canvas edge reads 1.8-2.5x the centre at FULL coverage.
  9fd7829d  The rejection sidecar says which kind of map it is - drizzle writes
            WEIGHT where every other strategy writes a rejection FRACTION.
  de347d88  The crop was DRAWN, not enforced: it never reached the enhance,
            where the exact-zero ring reads to a CNN as structure.
  8a5ded00  A saved file honours the view crop, at both ends of both paths.
  25390868  A/B is two comparisons where a crop is involved (455dc89e places the
            "before" half by its own frame).
  f7008182  Two crop lifetime bugs, found in the pre-release pass. A crop could
            LEAK across a file switch: ViewerState.DisplayCrop was never reset on
            a fresh load, so opening another file of the same dimensions carried
            the previous one's crop. And reverting an Enhance restored the wrong
            crop or none at all - the retained path trusted a stale cross-document
            remembered crop instead of the enhanced document's own SourceCrop,
            and the reload path restored nothing. The test written for the second
            failed on the first before it ever reached Enhance, which is what
            said they were two bugs and not one.

Not in the Store build, but in the span
  The macOS lane shipped in this window and cost two release runs before it
  worked. Contents/MacOS is nested=true in codesign's default resource rules, so
  NOTHING in it is sealed as a resource: every file there is code as far as
  codesign is concerned, and an unsigned data file fails the signing of the
  EXECUTABLE, several commands before any verify - naming whichever file the walk
  reached first, which is why it read as one bad file and was a whole class.
  v7.0.1621 died naming TianWen.AI.Imaging.pdb; stripping the pdbs only promoted
  LICENSE.EXCEPTION into the message for v7.1.1624. af2beddd signs every file and
  strips the debug artefacts (177 MB -> 135 MB), measured over seven bundle
  shapes on a real runner rather than guessed a third time.


KNOWN ISSUES IN THIS BUILD
================================================================================
  P11.2  The ? panel reports which SAS AI weights are missing and where it
         looked, but cannot fetch them: tools/tianwen-ai-models-fetch.ps1 is a
         repo script and a Store install cannot reach it. Closing it means an
         in-app download into %LOCALAPPDATA%\TianWen\models driven from that
         panel.

  P21    On a mosaic frame the single-channel views show the raw mosaic rather
         than the separated colour planes. ChannelView.DisplayedSourceChannel
         clamps to the channels the IMAGE has, and a 1-channel RGGB frame has
         one, so Red/Green/Blue all resolve to channel 0.

  P9/P10 A stray text fragment at the left edge, and a hand-off that may select
         the adjacent row. Both reported once, neither reproduced since; carried
         forward as unconfirmed rather than closed.

  SPCC   Photometric colour calibration is broadband only. Narrowband is blocked
         on data rather than maths: it needs per-star Gaia DR3 xp_sampled
         spectra, since a spectral type average cannot tell Ha absorption from
         emission over 3 nm.

  Layout Below about 730 px of window width the image pane arrives at zero width
         and the histogram overlay lands on the file list. Geometrically sound,
         but nothing has decided what should yield.

  About  The About banner concatenates the run attempt onto the version rather
         than separating it (7.1.16271 for 7.1.1627 attempt 1). Cosmetic, and
         present in every release so far: dotnet.yml composes -p:Version as
         ${VERSION_PREFIX}${VERSION_REV} with no separator, while -p:FileVersion
         is correct.
